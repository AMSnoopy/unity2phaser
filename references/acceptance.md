# 验收：契约核销 + 实机试玩

验收分两层：**自动核销**（机器能查的完整性）和**实机试玩**（人/自测确认体验）。两层都过才算完成。静态文件齐全不等于可玩；试玩通过不等于契约闭合——缺一不可。

## 第一层：契约自动核销

在输出项目根目录运行：

```bash
python <skill目录>/scripts/verify_output.py --project <输出目录> --inventory <输出目录>/conversion/inventory.json
```

脚本核对：
- **资源覆盖**：inventory 里每个图片/音频/字体文件，在输出 `assets/` 里都有对应文件（按原文件名；改名过的查 `conversion/asset-map.json`）
- **结构完整**：`index.html` 存在且引用本地 `lib/phaser.min.js`；场景文件齐全；无外部网络依赖
- **静态引用**：扫描 HTML/JS 里的字面量引用（script src、ES import、Phaser loader 路径），引用了不存在的文件立即报错
- **JS 语法**：本机有 node 时自动 `node --check` 每个 JS 文件

**出口条件**：报告 0 error。warning（外部 CDN、动态引用提示）逐条人工确认并在 progress.md 写明结论。缺失项不允许静默忽略——要么补齐，要么在 progress.md 的"缺口"段登记`源文件缺失/无法转换+原因+网页替代方案`。

## 第二层：实机自测

```bash
python <skill目录>/scripts/serve.py --project <输出目录> --port 8768
# 打开 http://127.0.0.1:8768/?muted=1（调试静音）；正式试玩去掉参数
```

> **改代码后重测必须绕过浏览器缓存**：URL 加随机参数（如 `?v=20260916-1`）或硬刷新。缓存会让你执行的仍是旧 JS，得出的结论全部作废。

> **自动化测试注意**：浏览器对被遮挡/失焦的窗口会把 rAF 降到极低甚至 0 帧，Phaser 的动画、tween、延迟回调、输入处理全部停滞——画面"卡住"先测 rAF（页面里数 1 秒帧数），把窗口置前再测，不要误判为游戏 bug。

按下面剧本走一遍（有浏览器自动化能力时截图留证；没有则逐项人工核对）：

### 剧本 A：完整通关
1. 打开游戏，观察开场/教学是否与原版流程一致
2. 完成第一个目标：操作、反馈（视觉+听觉+动画）顺序正确
3. 继续玩到游戏结束：完整结尾（成果展示/庆祝）不被截断
4. 结束后重开一次：能正常进入新一局

### 剧本 B：错误恢复
1. 故意答错/操作失败一次：错误反馈出现，允许重试
2. 使用帮助（如有）：帮助是示范引导而不是替玩家完成
3. 错误后完成目标：完成反馈正常
4. 输入门控：教学/演示未结束时乱点、或只跟着高亮点，**不能**跳过练习目标——原版有输入门控的必须保留门控，"狂点通关"说明判定被简化了

### 剧本 C：生命周期压力
1. 玩到一半重开：无残留对象、无旧音效、无幽灵输入
2. 再重开一次：依旧干净（叠加 bug 通常第二次才暴露）
3. 暂停→恢复（如有此功能）：tween/计时/音频全部暂停和恢复
4. 缩放窗口：画面等比缩放不错位（FIT 模式）

### 剧本 D：保真对照（有原版参照时）
- 原版视频/截图与转换版并排对照：开场画面、一个代表性操作的前后帧、结尾画面
- 布局比例、元素位置、颜色、字号目测一致；差异逐条记录
- **局部放大对照至少 2 处**（整体对照看不出 20~30px 的局部错位）：文字/图形在容器内是否居中、子元素相对父元素的偏移方向与距离。真实案例：整体 10 项对照 9 项一致，仍漏了"字母在圆形区域偏上 30px、蜜蜂贴图小 8%"，被最终用户发现
- **没有原版实机参照时**：与提供的录屏对照，标注哪些是"对照录屏确认"、哪些是"源码推断"

### 记录证据

结果写入 `conversion/acceptance.md`，格式：

```markdown
## 试玩记录
- 日期/版本：
- 剧本A 完整通关：✅/❌ + 一句话结论（❌ 时列出问题）
- 剧本B 错误恢复：✅/❌
- 剧本C 生命周期：✅/❌
- 剧本D 保真对照：N项一致 / M项差异（列表）

## 与原版的已知差异（全部列出，不隐瞒）
| # | 差异 | 原因 | 影响 | 状态（接受/待修/待定） |
|---|---|---|---|---|

## 无法验证项（诚实清单）
- 静态推断未实机核对：…
- 原版行为未知：…
```

**诚实边界**：改了代码不等于验证通过；截图静态一致不等于交互手感一致；没有对照证据就写 inferred，不写"与原版一致"。最终交付声明里区分三档：`已验证` / `推断未验证` / `未解决`。

## 对照证据的有效性

每次对照（剧本 D、局部放大、逻辑核验）的结果**绑定检查时的产物版本**：在 acceptance.md 该条记录旁写一行日期 + 产物标识（如当次 verify-report 的生成时间，或 git 提交号）。此后任何源码/素材/内容修改都会使**受影响的旧对照过期**——要么重做该对照，要么把它标注"已过期，待重对照"。**禁止**为了让旧结论继续显得有效而事后补记新版本号，那是伪造验证。最终交付声明里只统计未过期的对照。

## 出口门槛（全部满足才可交付）

- [ ] verify_output.py：0 error，warning 已逐条确认
- [ ] 剧本 A/B/C 全过，结果记录在 acceptance.md
- [ ] 剧本 D 完成（或明确说明无参照+推断清单）
- [ ] 最后一次代码/素材修改之后，受影响的对照已重做（无过期对照冒充有效）
- [ ] 契约缺口清单为空，或每条都有原因+替代方案
- [ ] progress.md 状态为"转换完成"
- [ ] （如执行增强）intentional-enhancements 已登记且不影响基线对照

未全过时：回到对应阶段修复，**不允许降门槛交付**；确有客观阻碍（源不全、无浏览器）时如实写明并冻结在当前状态。
